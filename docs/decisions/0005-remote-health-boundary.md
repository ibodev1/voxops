# 0005: Remote health boundary

**Status:** SUPERSEDED by [ADR 0010](0010-final-hackathon-architecture.md). The final remote boundary exposes POST /mcp and a GET /mcp route returning 405, in addition to health.

Add one API Gateway v2 HTTP API to the existing development stack. A single explicit `GET /health` route uses the existing Lambda through the standard payload v2 proxy integration. The `$default` stage is an automatically deployed stage, not a catch-all route. No default integration, proxy route, CORS, Function URL, or authentication system is configured. This is the smallest remote boundary needed to verify HTTP transport before choosing Alexa-compatible authorization.

The public response contains only `{"status":"ok"}`. Hono serves health before the MCP adapter's localhost guards so the gateway Host is accepted. All local MCP and repository routes remain under the original guards. Those guards are defense in depth, not caller authorization; the gateway's exact route allowlist prevents remote capability access. AWS IAM-authorized direct invocation remains available as in Milestone 5A.

Use stage throttling of 10 requests/second with a burst of 20, and seven-day JSON access logs containing only request ID, method, route key, status, and response/integration latency. Throttling is best effort, not a hard spending cap. Output actual runtime and access log group names instead of renaming the existing log group. The runtime stays ARM64, 256 MB, 10 seconds, with its existing execution policy. CDK adds a Lambda resource permission for this API's `/health` path (method/stage wildcards generated by the standard integration); only GET on the default stage is routed.

Remote MCP, repository REST routes, Cognito/OAuth, Alexa+ integration, writes, Bedrock, and frontend work remain deferred. The [authentication research note](../alexa-auth-research.md) records requirements without choosing a throwaway authentication layer. Deployment is manual using a non-root temporary-credential identity; tests and synthesis remain AWS-account-independent.
