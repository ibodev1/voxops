# 0006: Alexa Tier 1 service authentication and discovery

**Status:** Accepted; deployment and live interoperability checks remain manual.

Implement only client_credentials service authentication before user account linking. Alexa requires an exact resource parameter for Tier 1. Current Cognito documentation excludes resource binding for M2M client_credentials, so Cognito alone is not selected for this contract. See the [official-source research note](../alexa-auth-research.md). This decision does not select a Tier 2 identity provider.

The existing Lambda issues and verifies one-hour HS256 service JWTs using `jose`. Signature algorithm, issuer, exact audience, required claims, integer timestamps, maximum lifetime, service subject/client ID, and exact `mcp:service` scope are checked. Client_secret_basic credentials are compared through fixed-size SHA-256 digests and Node's timingSafeEqual; JWT signing/verification is delegated entirely to jose. Query/body credentials, other grants/scopes and resource mismatches are rejected. Token responses are no-store/no-cache with no refresh or ID token.

Import `voxops/dev/alexa-service-auth`; do not create credentials in CDK. It contains a stable client ID plus independent Base64-encoded client and signing secrets, each generated from at least 32 random bytes. The signing secret is used only for service JWTs. A small Zod-validated loader caches successful loads for warm invocations, retries failures and exposes no diagnostics or values. The execution role gains only GetSecretValue on that fixed secret ARN. Rotation requires replacing warm environments; immediate revocation and automatic rotation are not implemented.

Preserve the existing API/integration/runtime/log construct identities. Add exactly two public metadata GET routes, POST /oauth/token, and POST /mcp. Repository REST routes, catch-alls, GET MCP and CORS remain absent. Public health is unchanged. Lambda mode is explicit and always authenticates MCP, even without configuration or with a loopback Host. Hono's AWS adapter reconstructs the HTTPS URL using trusted API Gateway requestContext.domainName, which the auth layer validates; forwarded headers cannot select the issuer. Present Host/Origin must match that origin, and absence of Origin is accepted. Local Host/Origin guards and unconfigured loopback MCP remain available.

A valid service token permits initialize, notifications/initialized, ping, tools/list, and the current SDK's server/discover. All current tools can expose private GitHub data, so tools/call always returns HTTP 403 before invoking any tool. The HTTP gate inspects only the cloned top-level method, rejects batches/unknown methods, and passes the unchanged original request plus verified SDK AuthInfo to the official MCP handler. This avoids an HTTP 200 JSON-RPC tool error masquerading as an authorization denial. No protocol dispatch is duplicated.

Alexa explicitly disallows WWW-Authenticate in 401 responses. Reuse SDK verifyBearerToken but generate safe JSON 401/403 responses without its challenge helper. The installed SDK's metadata builder requires an authorization endpoint that Tier 1 lacks; construct the small RFC 9728 document using its exported type instead of advertising an unsupported endpoint. Public metadata advertises only capabilities actually implemented.

Keep seven-day minimal access logs and stage throttling at 10 requests/second, burst 20; no bodies, tokens, credentials or GitHub data are logged. No compute is added; the only additional recurring resource is the manually created secret. Deterministic tests cover route/IAM allowlists and real SDK discovery with zero GitHub adapter calls. Live testing and Alexa compatibility remain operator verification tasks.

Deferred to 5D: Tier 2 authorization_code + PKCE, refresh tokens, user identity/provider selection (including possible Cognito), consent/account linking, and GitHub user/repository association. Service credentials must never become user authorization. Write actions and Alexa Add-on deployment are outside this milestone.
