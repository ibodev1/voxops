# Historical M6: Alexa+ Add-on readiness

This checklist records the attempted Add-on path. The final hackathon submission uses the working self-hosted MCP server and simulated Alexa+ web experience; no Alexa Add-on is deployed. See the [current README](../README.md).

- **Endpoint:** use the `ApiEndpoint` stack output plus `/mcp`. API Gateway exposes POST for MCP requests and, after the final spec fix is manually deployed, GET returning 405 for unsupported standalone SSE. `GET /health` is a separate probe.
- **Account linking:** disabled; the four tools operate on the same public data for all callers. **Service authentication:** none for this public MCP server. This interpretation follows the [account-linking guide](https://developer.amazon.com/docs/alexaplus/add-ons/mcp-toolkit-account-linking.html) and [authentication guide](https://developer.amazon.com/docs/alexaplus/add-ons/mcp-toolkit-authentication.html); verify it in the live Alexa flow because the [quickstart](https://developer.amazon.com/docs/alexaplus/add-ons/mcp-toolkit-quickstart.html) includes a broad authentication checklist.
- **Tools:** `get_repository_status`, `list_open_issues`, `list_pull_requests`, `list_workflow_runs`; all read-only. Lambda allowlist: `VOXOPS_PUBLIC_REPOSITORIES=ibodev1/voxops`. Each call independently confirms GitHub reports a public repository.
- **Repository prerequisite:** formerly blocked when `ibodev1/voxops` was private; it is now public and all four live tools have passed the remote MCP smoke test.
- **Before `alexa-ai new`:** obtain a working public HTTPS `ApiEndpoint`, pass remote health and MCP smoke checks, install/sign in to the current Alexa AI CLI with an authorized developer account, choose the intended Add-on name and locale, then check current CLI help. The [official quickstart](https://developer.amazon.com/docs/alexaplus/add-ons/mcp-toolkit-quickstart.html) shows `alexa-ai new mcp --name <name> --locale en-US --mcp-server-url <ApiEndpoint>/mcp`; leave account linking disabled.
- **Before `alexa-ai deploy`:** inspect the generated manifest and confirm its default endpoint is exactly the public HTTPS `/mcp` URL, no account-linking/authentication credentials are configured, the four tools are discoverable, and all required Add-on metadata, privacy/terms information, and developer account prerequisites from current CLI guidance are complete. Reconcile the quickstart authentication checklist with the generated no-auth configuration before deploying. No Add-on is created or deployed in M5E.
- **Web Simulator:** connect and list four tools; invoke each for `ibodev1/voxops`; confirm a nonallowlisted name yields a clear tool error, private responses cannot return data, no write tools appear, and no account-linking prompt or token is requested. Record real Alexa behavior before claiming compatibility.
